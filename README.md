## Local development

Requires Node.js 22+ or Node.js 20.12+ for the built-in
[`process.loadEnvFile`](https://nodejs.org/api/process.html#processloadenvfilepath).
No dependencies need to be installed.

From the project root, edit `.env`, then start the app:

```bash
node src/index.js
```

Open http://localhost:3000 (or the port set in `.env`). Stop with `Ctrl+C`.
Restart the server after changing `.env`.

The app automatically loads `.env` from the project root, even when started from
another directory. Existing environment variables take precedence over `.env`;
if the file is absent, supply the complete configuration through the process
environment (for example, through Docker or Kubernetes).

Runtime settings and URL bases are defined in `.env`. Missing or empty required
variables stop startup with a message naming the variable. `SERVICE_NAME` sets
the app name and Grafana link. `PROJECT_NAME` names the repository and determines
the dev/prod endpoints and project Variables link; it may differ from the service name.
`DEPLOYMENT_ENV` sets the environment reported in logs. `OTEL_SERVICE_NAME`
remains a separate platform variable for telemetry and is not required by this
template.

For example:

```dotenv
PROJECT_NAME=test-for-demo-1
SERVICE_NAME=api
REPO_URL=https://github.com/DLR-easydeploy/
VARIABLES_URL=https://<portal host>/projects/
```

This produces `https://github.com/DLR-easydeploy/test-for-demo-1`. Set
`REPO_URL_SUFFIX=.git` to produce `https://github.com/DLR-easydeploy/test-for-demo-1.git`.
The GitHub card opens this address in the browser. Each clone step on the welcome
page has an HTTPS / SSH switch. SSH is selected by default; changing the selection
updates both clone examples. Choose one of these commands:

HTTPS:

```bash
git clone https://github.com/DLR-easydeploy/test-for-demo-1.git
cd test-for-demo-1
```

SSH:

```bash
git clone git@github.com:DLR-easydeploy/test-for-demo-1.git
cd test-for-demo-1
```

Both clone addresses are derived from the same repository host and path, with a
single `.git` suffix. SSH requires a key registered with your Git host.

Changing `PROJECT_NAME` updates the repository, dev/prod and Variables links.
The Variables card opens `VARIABLES_URL` + `test-for-demo-1`.

Application links always use HTTPS and the configured `BASE_DOMAIN`.
The current configuration is:

```dotenv
BASE_DOMAIN=<platform domain>
DEV_URL_SUFFIX=-dev
```

This generates `https://test-for-demo-1-dev.<platform domain>/` for dev and
`https://test-for-demo-1.<platform domain>/` for prod. These welcome-page links
are composed from `.env` and can be out of date; the real address of each
service is its `url` in the project detail (`GET /api/v1/projects/test-for-demo-1`).

| Link | Generated address |
|---|---|
| Git repository (browser) | `REPO_URL` + `/` + `PROJECT_NAME` + `REPO_URL_SUFFIX` |
| Git clone (HTTPS) | `https://<repository host>/<repository path>.git` |
| Git clone (SSH) | `git@<repository host>:<repository path>.git` |
| Dev | `https://` + `PROJECT_NAME` + `DEV_URL_SUFFIX` + `.` + `BASE_DOMAIN` + `/` |
| Prod | `https://` + `PROJECT_NAME` + `PROD_URL_SUFFIX` + `.` + `BASE_DOMAIN` + `/` |
| Project variables | `VARIABLES_URL` + `/` + `PROJECT_NAME` |
| Grafana dashboard | `GRAFANA_URL` + `/` + `GRAFANA_DASH_PREFIX` + `SERVICE_NAME` + `GRAFANA_DASH_SUFFIX` + `/` + `SERVICE_NAME` |

Base URLs work with or without a trailing `/`; the app inserts one separator.
`VARIABLES_URL` includes the `/projects/` path, and `GRAFANA_URL` includes `/d/`.
Prefixes and suffixes are optional; omit them when not needed. The supplied
configuration uses `-dev` for dev and `easydeploy-` for the Grafana UID.
`PORTAL_URL` remains the complete address for the portal home page.
The app builds these URLs in JavaScript; variable references inside `.env` are
not expanded. The old `DEV_URL`, `PROD_URL`, and `GRAFANA_DASH`
environment variables are replaced by these bases and suffixes.

Project creation copies the configured Git template's default branch into one first
commit, replaces `PROJECT_NAME`, `SERVICE_NAME`, `PORT` and `REPO_URL` in `.env`,
and generates `easydeploy.yaml` with the requested project, team, service and port.
The descriptor builds the root `Dockerfile`; other template files stay intact.
Service settings, including `otel.runtime`, belong to the matching entry under
`services` in `easydeploy.yaml`. Update that entry while keeping the existing
project and team configuration.
Keep only public defaults in the tracked `.env`; manage secrets through EasyDeploy.

For Docker, the image includes those defaults; `--env-file` can override them:

```bash
docker build -t easydeploy-template .
docker run --rm --env-file .env -p 127.0.0.1:3000:3000 easydeploy-template
```

If you change `PORT` in `.env`, update the container port (the last number in
`-p`) to match. Rebuild after changing the defaults bundled in `.env`.

        ## Platform overview

        Runs on **EasyDeploy** — AKS cluster, shared `easy-deploy` namespace.
        All services deploy to namespace `easy-deploy` (both dev and prod).
        Services reach each other via short DNS names: `http://api:8000`, `http://db:5432`.

        - **Deployments** — push to `main` → deploys to dev. Tag push → prod.
        - **Variables** — manage environment variables and secrets on the project page. No secrets in git.
        - **Grafana Cloud** — metrics, traces, logs via OTel.
        - **NetworkPolicy** — default-deny external. Only intra-namespace traffic + ingress controller.

        ## Deploy flow

        ```
        push to main
          → self-hosted runner: build images → push to registry
          → generate manifests → commit to EasyDeploy repo
          → platform deploys to easy-deploy namespace
          → portal notified when healthy
        ```

        Prod:
        ```
        git tag v1.0.0 && git push origin v1.0.0
          → re-tag images as v1.0.0
          → platform deploys to easy-deploy namespace
        ```
